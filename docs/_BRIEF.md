# Задание: демо нового сайта для холодного звонка

Сделайте демо-версию нового сайта для компании из вашего задания. Оператор покажет демо компании на холодном звонке: «мы уже сделали вам новый сайт, посмотрите». Демо должно быть заметно лучше текущего сайта с первого взгляда. Демо должно быть про эту компанию, а не шаблоном.

Образец готового результата: `/Users/k41n/projects/saransk-site/docs/saranskkonserv/` (index.html, call.md). Памятка с приёмами и ошибками: `/Users/k41n/projects/saransk-site/docs/_PATTERN.md`. Прочитайте памятку и call.md образца. Не копируйте дизайн образца: у каждого клиента свои шрифты, своя композиция, свой характер.

Перед вёрсткой вызовите скилл `frontend-design:frontend-design` (Skill tool) и следуйте ему.

## Жёсткие правила

1. **Корпоративные цвета.** Палитра демо строится только на цветах логотипа и текущего сайта клиента. Проверьте цвета по CSS и логотипу, не по догадке. Добавлять можно только нейтральные цвета и оттенки фирменных.
2. **Ничего не выдумывайте.** Никаких несуществующих цифр, наград, отзывов, цен, годов. Если данных нет на сайте клиента, не делайте этот блок.
3. **Браузер.** НЕ используйте Playwright MCP: он общий, параллельные агенты мешают друг другу. Контент собирайте через curl (учитывайте кодировку windows-1251: `iconv -f cp1251 -t utf-8`). Снимки делайте отдельным процессом headless Chrome:
   `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --user-data-dir=/Users/k41n/projects/saransk-site/docs/<slug>/.chrome --window-size=1280,7000 --screenshot=<файл.png> <url>`
   Для телефона: `--window-size=390,7000`. После работы удалите папку `.chrome`. Если Chrome нет, используйте `npx playwright screenshot`.
4. **Файлы.** Пишите только в `/Users/k41n/projects/saransk-site/docs/<slug>/`. Не пишите в /tmp. Не трогайте git и чужие папки.
5. **Вёрстка.** Статический HTML + CSS, минимум JS без библиотек, без сборки. Все пути относительные. В head: `<meta name="robots" content="noindex,nofollow">`, viewport, `lang="ru"`. Не используйте `loading="lazy"`.
6. **Подвал.** Мелкая строка: «Демо-версия. Материалы принадлежат <название компании>».

## Порядок работы

1. Снимите текущий сайт клиента headless Chrome на 1280 и 390 в `_old_desktop.png` и `_old_mobile.png`. Посмотрите снимки через Read.
2. Соберите контент: главная, каталог, о компании, контакты, прайс. Реальные тексты, продукция и услуги, телефоны, адрес, e-mail, реквизиты.
3. Скачайте логотип и 8–15 реальных фото в `img/`. Сожмите большие (`magick` или `sips`), до 2 МБ в сумме. Если фото мало или они мелкие, стройте дизайн на типографике, цвете и SVG-графике, а не на стоковых фото.
4. Сверстайте `index.html`: первый экран (что компания делает + телефон + кнопка), продукция или услуги с реальным содержимым, преимущества только из фактов сайта, о компании, контакты с кликабельным `tel:` и адресом.
5. Снимите демо на 1280 и 390 в `_preview_desktop.png` и `_preview_mobile.png` (file:// для headless Chrome работает). Посмотрите снимки через Read. Исправьте наезды, обрезанный текст, битые картинки, пустые блоки, горизонтальную прокрутку. Повторяйте до чистого результата.
6. Напишите `call.md` по образцу: компания, телефон и источник, кого спросить, **3 проблемы текущего сайта, которые вы сами увидели и проверили**, первая фраза оператора, что показать в демо, чего не говорить. Имя руководителя берите со страницы контактов клиента или из https://investrm.ru/contacts_navigator/enterprises/. Пишите короткими простыми предложениями.

## Финальный ответ

Верните только: пути файлов, итоговую палитру, список блоков страницы, 3 проблемы из call.md, что не удалось собрать, какие дефекты остались. Без пересказа процесса.
