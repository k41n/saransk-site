# Проект «Холодные звонки по Саранску»

Мы продаём компаниям новый сайт за 2–3 дня и 25 раундов правок. Оператор звонит в компанию и показывает готовое демо нового сайта.

## Состав проекта

- `docs/` — папка, которую GitHub Pages публикует по адресу https://k41n.github.io/saransk-site/
- `docs/<slug>/index.html` — демо нового сайта клиента. Клиент получает только эту ссылку.
- `docs/<slug>/call.md` — сценарий звонка: телефон, кого спросить, три проблемы сайта, первая фраза.
- `docs/<slug>/compare.html` — внутренняя страница «Было / Стало».
- `docs/index.html` — внутренний список компаний в порядке звонка.
- `docs/_BRIEF.md` — правила вёрстки демо. `docs/_PATTERN.md` — приёмы и ошибки. Прочитайте оба файла перед вёрсткой.
- `data/` — рабочие данные. GitHub Pages эту папку не публикует, но репозиторий публичный.
  - `companies.csv` — рейтинг 51 компании.
  - `improvable_with_phone.csv` — 23 компании с улучшаемым сайтом и телефоном.
  - `call_list_top10.csv`, `call_list_top10.md` — первая десятка для звонка.
  - `build_sales_site.py` — генератор `compare.html`, `docs/index.html` и списков.
  - `shots/` — снимки сайтов из визуальной оценки.
  - `report.html` — отчёт о первом этапе работы.

## Жёсткие правила

1. Делайте демо только в корпоративных цветах клиента. Проверяйте цвета по CSS и логотипу клиента.
2. Ничего не выдумывайте. Не добавляйте цифры, награды, отзывы, цены и фото, которых нет на сайте клиента.
3. Статус «сайт не найден» не означает «сайта нет». Оператор не говорит клиенту «у вас нет сайта».
4. Отдавайте поиск, оценку, вёрстку и снимки субагентам на Sonnet. Главная модель планирует и проверяет.
5. Проверяйте каждое демо по снимкам `_preview_desktop.png` и `_preview_mobile.png`. Отчёт субагента не заменяет просмотр.
6. Ставьте на каждую страницу `<meta name="robots" content="noindex,nofollow">`.
7. Используйте только статический HTML и CSS, минимум JS, относительные пути, без сборки.
8. Клиент получает только ссылку на демо. Список, `compare.html` и `call.md` внутренние.
9. Спросите разрешение у пользователя перед каждой публикацией.

## Сценарий звонка (`call.md`)

- Указывайте только три проблемы сайта, которые вы сами проверили на живом сайте.
- Оператор не говорит «у вас плохой сайт» и не называет цену.
- Оператор не называет значок, который нарисовали мы, логотипом компании.
- Указывайте источник каждого телефона и имени руководителя.

## Технические заметки

- Не используйте Playwright MCP в параллельных субагентах: он общий.
- Снимок на ширине 1280: headless Chrome с `--window-size=1280,<высота>`.
- Снимок на ширине 390: `npx playwright screenshot --channel chrome --viewport-size=390,900 --full-page <url> <файл>`. Headless Chrome не снимает окно уже 500 px.
- Страницу выше 16384 px снимайте частями и склеивайте через `magick`.
- Playwright блокирует `file://`. Запустите `python3 -m http.server` в `docs` и остановите сервер после работы.
- Не используйте `loading="lazy"` в демо: атрибут ломает снимок всей страницы.
- Старый сайт на странице сравнения показывайте снимком. Часть сайтов работает только по http или запрещает iframe.
- После правки `call.md` запустите `python3 data/build_sales_site.py`.
- Генератор не обновляет миниатюры. Обрежьте верх `_preview_desktop.png` до 1280×800 и уменьшите до 640×400 в `docs/_assets/thumbs/<slug>.jpg`.
- Новую компанию добавьте в список компаний внутри `data/build_sales_site.py`.
- Файл `docs/.nojekyll` обязателен: без него GitHub Pages не отдаёт папку `_assets`.

## Публикация

```
git add docs data CLAUDE.md
git commit -m "<что изменилось>"
git push
```

GitHub Pages собирает сайт из ветки `main`, папка `/docs`. Сборка занимает 1–2 минуты.
